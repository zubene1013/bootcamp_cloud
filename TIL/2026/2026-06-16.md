## Key concepts learned

- **Service**: Pod는 죽으면 IP가 바뀌고 여러 개일 때 접근 경로가 불명확하므로, Service가 고정 진입점과 로드밸런서 역할을 수행
- **NodePort**: 클러스터 외부에서 고정 포트(30000~32767)로 Pod에 접근 가능한 Service 타입
- **ClusterIP**: 클러스터 내부에서만 접근 가능한 Service 타입 (기본값)
- **Ingress**: URL 경로 기반으로 여러 Service에 트래픽을 분기하는 리소스
- **RestartPolicy**: Pod 안 컨테이너 종료 시 K8s가 재시작할지 결정하는 규칙 (OnFailure 등)
- **ImagePullPolicy**: Pod 시작 시 Docker 이미지를 언제 받을지 결정 (IfNotPresent, Always 등)
- **Label**: Pod를 식별하고 그룹화하기 위한 key-value 메타데이터로, Service의 selector로 활용

## Commands / Configuration

### Service 생성 및 조회

```bash
kubectl apply -f service-nodeport.yaml
kubectl apply -f service-clusterip.yaml
kubectl get svc
kubectl run test-pod --image=curlimages/curl --rm -it --restart=Never -- curl http://nginx-clusterip:80
```

### NodePort Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  type: NodePort
  selector:
    app: nginx
  ports:
  - port: 80
    targetPort: 80
    nodePort: 30080
```

### ClusterIP Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-clusterip
spec:
  selector:
    app: nginx
  ports:
  - port: 80
    targetPort: 80
```

### Ingress Controller 설치 및 구성

```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.10.1/deploy/static/provider/cloud/deploy.yaml
kubectl get pods -n ingress-nginx
kubectl apply -f ingress.yaml
kubectl get ingress
```

### Ingress 경로 기반 라우팅

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
  - http:
      paths:
      - path: /nginx
        pathType: Prefix
        backend:
          service:
            name: nginx-service
            port:
              number: 80
      - path: /apache
        pathType: Prefix
        backend:
          service:
            name: apache-service
            port:
              number: 80
```

### RestartPolicy와 ImagePullPolicy

```yaml
spec:
  restartPolicy: OnFailure
  containers:
  - name: nginx-container
    image: nginx:1.14.2
    imagePullPolicy: IfNotPresent
```

### 멀티컨테이너 Pod (pod3)

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pod3
spec:
  containers:
  - name: nginx-container
    image: nginx:1.14.2
  - name: redis-container
    image: redis:latest
  - name: busybox-container
    image: busybox:1.28
    command: ['sh', '-c', 'echo "Hello, Kubernetes!" && sleep 3600']
    imagePullPolicy: IfNotPresent
```

```bash
kubectl apply -f pod3.yaml
kubectl get pods
```

### kubectl edit — 실행 중 리소스 수정

```bash
kubectl edit pod pod3
kubectl get pods --show-labels
```

### command로 시작 명령어 실행

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pod5
spec:
  containers:
  - name: nginx-container
    image: nginx:1.14.2
    command: ["sh", "-c", "touch abc.txt && nginx -g 'daemon off;'"]
```

```bash
kubectl apply -f pod5.yaml
kubectl exec pod5 -- ls
```

### Label CRUD 명령어

```bash
# 추가
kubectl label pods nginx-pod unhealthy=true
kubectl label pods --all status=unhealthy

# 수정
kubectl label --overwrite pods nginx-pod status=healthy

# 삭제
kubectl label pods nginx-pod app-

# 조회
kubectl get pods --show-labels
kubectl get pods -L app,env
kubectl get pods -l app=nginx
kubectl label pods nginx-pod --list
```

### kubectl run — 빠른 Pod 생성

```bash
kubectl run pod9 --image=nginx
kubectl run pod9 --image=nginx --dry-run=client -o yaml
kubectl run pod9 --image=nginx --restart=Never --port=80
kubectl run pod9 --image=nginx --env="ENV=prod"
kubectl run -it pod9 --image=nginx -- bash
kubectl run pod9 --image=curlimages/curl --rm -it --restart=Never -- curl http://nginx-service
```

### kubectl replace — 리소스 교체

```bash
kubectl replace -f new-pod.yaml
kubectl get pod pod1 -o yaml
```

### kubectl top — CPU/Memory 조회

```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
kubectl top pods
kubectl top nodes
```
