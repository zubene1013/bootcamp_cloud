## Key concepts learned

- **Kubernetes Service**: Pod을 고정된 이름으로 찾게 해주는 리소스. Pod은 재시작 시 IP가 변경되므로 Service 이름으로 안정적 접근 가능
- **Service 타입 (ClusterIP vs NodePort)**: ClusterIP는 클러스터 내부 통신용(redis, db, worker), NodePort는 외부 접속 노출용(producer, dashboard)
- **포트(Port)**: 프로그램이 외부 요청을 받는 출입문 번호. 요청을 받는 앱(웹, 대시보드)만 필요하며, 내보내기/접속만 하는 앱(producer, worker)은 불필요
- **Kubernetes manifest**: "이렇게 띄워줘"라고 적은 YAML 설계도. 보통 리소스 1개당 YAML 1개이며 여러 리소스는 `---`로 구분
- **CNI (Calico)**: 클러스터 내 Pod 간 통신을 가능하게 하는 네트워크 플러그인. kubeadm init 직후 노드가 NotReady 상태이며 CNI 설치로 Ready로 변환됨
- **AWS Budgets**: 월별/분기별/연간 비용 예산 설정 및 임계값 초과 시 알림 발송. 예산 초과 시 자동화된 대응(인스턴스 중지 등) 가능
- **AWS Cost Explorer**: 과거 AWS 비용 및 사용량 데이터를 시각화 분석하는 도구. 이미 붙은 태그 데이터만 필터링 가능하며 소유자 자동 판별 불가
- **AWS Anomaly Detection**: 머신러닝으로 비정상적인 지출 패턴을 동적으로 감지. 고정 예산 알림과 달리 과거 패턴 대비 통계적 비정상 감지
- **RDS 저장 데이터 vs 전송 데이터 암호화**: 저장 데이터는 KMS로 암호화, 전송 데이터는 AWS 제공 루트 인증서로 SSL/TLS 암호화
- **S3 서버측 암호화**: KMS 키로 암호화하고 KMS 키 정책에서 복호화 권한을 제어하여 고객별 데이터 독립성 보장
- **DynamoDB 읽기 일관성**: 최종적 일관성(기본, RCU 절반)은 최신 데이터 미보장. 강력하게 일관된 읽기(ConsistentRead:true)는 항상 최신 데이터 반환
- **AWS Lambda**: 서버리스 컴퓨팅으로 최대 15분 실행, 코드 실행 시간과 요청 횟수만 과금. 단기 보고서 생성(10분 이내)에 최적
- **Amazon EventBridge**: 이벤트 기반 아키텍처 서비스. cron 표현식으로 스케줄 기반 트리거 및 이벤트 패턴 기반 라우팅 지원
- **ElastiCache for Redis**: 인메모리 데이터 저장소로 마이크로초 지연시간 제공. RDB 스냅샷/AOF로 데이터 영속성 보장, Multi-AZ로 고가용성 제공
- **DynamoDB vs ElastiCache**: DynamoDB는 확장성 있는 카탈로그용, ElastiCache for Redis는 세션 저장 및 캐싱용(대기시간 최소화)
