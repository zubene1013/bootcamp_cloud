## Key concepts learned

- **systemctl enable** — 재부팅 후에도 서비스가 자동으로 시작되도록 등록하는 명령어 (start만으로는 재부팅 시 중단됨)
- **AMI (Amazon Machine Image)** — 현재 서버 상태를 이미지로 저장하여 동일하게 복제 가능한 기능
- **Elastic IP의 한계** — 실무에서는 Auto Scaling 환경에서 고정 IP 대신 ALB의 DNS 이름으로 접근 (뒤의 인스턴스 개수/IP가 변해도 ALB DNS 하나로 통일)
- **UserData 스크립트** — EC2 인스턴스 시작 시 자동으로 실행되는 초기화 스크립트 (패키지 설치, 서비스 시작, 웹페이지 커스터마이징 등)
- **시작 템플릿 (Launch Template)** — Auto Scaling 그룹이 참조하는 EC2 설정 템플릿 (AMI, 인스턴스 타입, 키페어, 보안그룹, UserData 등 포함)
- **Auto Scaling 그룹 (ASG)** — 최소/최대/원하는 용량을 설정하여 자동으로 인스턴스를 늘렸다 줄었다 하는 기능
- **ALB (Application Load Balancer)** — 들어오는 요청을 대상 그룹의 여러 인스턴스에 분산시키는 로드밸런서
- **CIDR 표기법 (A.B.C.D/E)** — 네트워크 범위를 표현하는 방식으로, E는 앞에서부터 고정되는 네트워크 비트 수를 의미
- **네트워크 주소의 필수 조건** — 주어진 CIDR에서 네트워크 주소는 호스트 비트 영역이 반드시 전부 0이어야 함 (고정 비트는 임의로 변경 불가)
- **/E 크기와 IP 개수의 역관계** — /E 숫자가 클수록 고정 부분이 많아져 사용 가능한 IP 개수가 감소 (/16=65,536개 > /24=256개 > /26=64개 > /28=16개)
- **Service Quota** — AWS 리전당 기본 VPC 제한 개수 (기본값 5개, 초과 시 기존 리소스 삭제 필요)

## Commands / Configuration

### Apache 설치 및 서비스 등록

```bash
sudo -s
apt update && apt install apache2 -y
systemctl start apache2
systemctl status apache2
systemctl enable apache2
```

### UserData 스크립트 예시

```bash
#!/bin/bash
apt update -y
apt install apache2 -y
systemctl start apache2
systemctl status apache2
systemctl enable apache2
echo "<h1>Hello $(hostname -f)</h1>" > /var/www/html/index.html
```

### 리소스 삭제 순서 (Auto Scaling 환경)

```
1. 시작 템플릿 삭제
2. 로드밸런서 삭제
3. Auto Scaling 그룹 삭제 (EC2보다 먼저 — 안 그러면 ASG가 삭제된 인스턴스를 감지해 자동으로 새 인스턴스 생성)
4. 대상 그룹 삭제
5. EC2 인스턴스 종료
```
