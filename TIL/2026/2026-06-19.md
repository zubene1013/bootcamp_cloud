## Key concepts learned

- **Service**: Pod의 재시작으로 인한 IP 변경 문제를 해결하기 위해 고정 IP/DNS와 로드밸런싱을 제공하는 추상화 계층
- **ClusterIP**: 클러스터 내부 전용 서비스로, CoreDNS를 통해 서비스 이름으로 접근 가능
- **NodePort**: 외부 브라우저에서 localhost:포트번호로 접근 가능한 서비스 (포트 범위: 30000~32767)
- **LoadBalancer**: 클라우드 환경에서 자동으로 클라우드 로드밸런서 생성 및 공인 IP 할당
- **Ingress**: 포트 80 하나로 경로/도메인에 따라 여러 서비스로 라우팅하는 리소스
- **Ingress Controller**: Ingress 리소스의 라우팅 규칙을 실제로 처리하는 구현체 (NGINX Ingress Controller)
- **환경변수(env)**: 컨테이너 실행 시 앱이 참조하는 설정값으로, Pod YAML에 직접 작성 가능
- **ConfigMap**: 환경변수를 외부 리소스에 저장하고 Pod에서 참조하는 방식 (평문 저장, 민감 정보 불가)

## Commands / Configuration

### Service 설정

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```

### ClusterIP 확인

```bash
kubectl exec -it ubuntu-test -- bash
curl http://nginx-clusterip-service
```

### NodePort 설정

```yaml
type: NodePort
ports:
- port: 80
  targetPort: 80
  nodePort: 30007
```

### LoadBalancer 설정

```yaml
type: LoadBalancer
```

```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.11.2/deploy/static/provider/cloud/deploy.yaml
kubectl get all -n ingress-nginx
kubectl get ingressClass
```

### 경로 기반 Ingress

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
  - http:
      paths:
      - path: /app1
        pathType: Prefix
        backend:
          service:
            name: app1-service
            port:
              number: 80
      - path: /app2
        pathType: Prefix
        backend:
          service:
            name: app2-service
            port:
              number: 80
```

### 호스트 기반 Ingress

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress-host
spec:
  ingressClassName: nginx
  rules:
  - host: app1.com
    http:
      paths:
      - pathType: Prefix
        path: "/"
        backend:
          service:
            name: app1-service
            port:
              number: 80
  - host: app2.com
    http:
      paths:
      - pathType: Prefix
        path: "/"
        backend:
          service:
            name: app2-service
            port:
              number: 80
```

### 환경변수(env) 설정

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: env-basic-pod
spec:
  containers:
  - name: nginx-containers
    image: nginx
    env:
    - name: GREETING
      value: "Warm greetings to"
    - name: HONORIFIC
      value: "The Most Honorable"
    - name: NAME
      value: "Kubernetes"
    - name: MESSAGE
      value: "$(GREETING) $(HONORIFIC) $(NAME)"
```

### 환경변수 확인

```bash
kubectl exec env-basic-pod -- printenv
kubectl exec env-basic-pod -- env
kubectl exec -it env-basic-pod -- bash
root> echo $MESSAGE
```

### ConfigMap 생성

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: game-configmap
data:
  player_initial_lives: "3"
  ui_properties_file_name: "user-interface.properties"
  game.properties: |
    enemy.types=aliens,monsters
    player.maximum-lives=5
  user-interface.properties: |
    color.good=purple
```

### ConfigMap 조회

```bash
kubectl get configmaps
kubectl get cm
kubectl describe cm game-configmap
```

### ConfigMap 개별 참조 (env.valueFrom)

```yaml
env:
- name: PLAYER_INITIAL_LIVES
  valueFrom:
    configMapKeyRef:
      name: game-configmap
      key: player_initial_lives
```

### ConfigMap 한꺼번에 참조 (envFrom)

```yaml
envFrom:
- configMapRef:
    name: game-configmap
```
