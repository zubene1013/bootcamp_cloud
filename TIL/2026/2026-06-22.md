## Key concepts learned

- **Secret**: ConfigMap과 동일한 구조이지만 비밀번호, 토큰, 인증서 등 민감한 정보 저장용으로 사용
- **base64 인코딩**: Secret의 저장 방식으로, 암호화가 아니므로 누구나 디코딩 가능
- **etcd 암호화**: 실제 민감 정보 보호를 위해서는 etcd 수준에서 별도의 암호화 설정 필요
- **namespace 단위 적용**: Secret은 특정 namespace 범위 내에서만 적용
- **data 필드**: base64로 인코딩된 값을 직접 입력하는 방식
- **stringData 필드**: 평문으로 입력하면 Kubernetes가 자동으로 base64 인코딩하는 방식

## Commands / Configuration

### Secret 정의 (data vs stringData)

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: secret-test
data:
  email: aW5reTQ4MzJAZGF1bS5uZXQ=    # base64 인코딩값
stringData:
  username: root      # 평문 → K8s가 자동 인코딩
  password: "1234"
  database: testdb
```
