## Key concepts learned

- **Redis**: 데이터를 메모리(RAM)에 저장하는 초고속 임시 저장소로, 주로 캐시 또는 큐로 사용되며 디스크 DB보다 읽기·쓰기가 훨씬 빠름
- **Redis의 역할 (버퍼)**: 요청이 몰릴 때 DB가 과부하되지 않도록 완충 역할을 하며, 투표 앱에서 폭주하는 투표를 임시로 받아두는 큐 역할
- **Redis의 역할 (캐시)**: URL 단축 서비스에서 자주 찾는 주소를 미리 저장해두어 DB 조회 없이 빠르게 응답
- **Container와 Pod의 관계**: 컨테이너는 Pod 안에 담기고, 하나의 Pod 안에 여러 컨테이너가 있을 수 있음
- **Pod와 Kubernetes의 관계**: Pod은 Kubernetes가 관리하는 최소 단위로, Kubernetes는 Pod을 어느 Worker에 띄울지, 죽으면 복구할지, 확장할지 관리
- **Kubernetes 관리 단위**: Kubernetes는 컨테이너를 직접 관리하지 않고 항상 Pod을 통해서 관리하며, 명령도 "Pod 띄워" 단위로 실행
- **apiVersion 판단 기준**: kind를 먼저 결정한 후, 해당 리소스가 속한 API 그룹/버전을 apiVersion으로 지정
- **kind 판단 기준**: 만들려는 리소스가 무엇인지 결정하는 것이 먼저이며, StatefulSet과 Deployment 등 다양한 kind가 존재
