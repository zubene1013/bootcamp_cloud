## Key concepts learned

- **Docker의 3가지 데이터 타입**: 이미지 데이터(read-only), 컨테이너 데이터(휘발성), 볼륨 데이터(영속성) - 각각의 특성과 용도가 다름
- **데이터 영속성 관리 방법**: Docker Volume(호스트 저장소 추상화)과 Bind Mount(호스트 디렉터리 직접 연결)으로 컨테이너 삭제 후에도 데이터 유지 가능
- **환경변수 주입**: docker run -e로 단일 변수 주입, --env-file로 파일 기반 다중 변수 주입 가능하며, 이미지 수정 없이 실행 환경에 따라 값 변경 가능
- **IaC (Infrastructure as Code)**: 코드로 인프라를 구축하는 방법론으로 Dockerfile, docker-compose, K8s yaml, terraform 등이 있음
- **Dockerfile**: 이미지 생성을 위한 템플릿으로, 명령어 실행 결과가 레이어로 누적되어 최종 이미지 생성
- **WORKDIR**: 컨테이너 내부의 기준 작업 디렉터리 설정으로, 이후 RUN, COPY, CMD 등의 명령이 이 디렉터리 기준으로 실행됨
- **RUN vs CMD vs ENTRYPOINT**: RUN은 빌드 시 실행되어 이미지에 저장, CMD는 docker run 시 실행되며 덮어쓰기 가능, ENTRYPOINT는 docker run 할 때 덮어쓰기 어려움
- **멀티스테이지 빌드**: FROM ... AS 문법과 COPY --from으로 이전 스테이지의 결과물을 현재 스테이지로 복사 가능

## Commands / Configuration

### Docker Volume 명령어

```bash
# 볼륨 생성
docker volume create [VOLUME_NAME]

# 볼륨 목록 확인
docker volume ls
docker volume list

# 볼륨 상세 정보
docker volume inspect [VOLUME_NAME]

# 볼륨 삭제
docker volume rm [VOLUME_NAME]
docker volume remove [VOLUME_NAME]
docker volume rm -f [VOLUME_NAME]  # 강제 삭제

# 미사용 볼륨 모두 삭제
docker volume prune
docker volume prune -f  # 확인 없이 바로 삭제
```

### Docker Volume 사용 (컨테이너 실행 시)

```bash
# Named Volume 사용
docker run -d --name [CONTAINER_NAME] -p [HOST_PORT]:[CONTAINER_PORT] -v [VOLUME_NAME]:[CONTAINER_PATH] [IMAGE]

# 예시
docker run -d --name my-nginx -p 1234:80 -v web-data:/usr/share/nginx/html nginx

# Bind Mount 사용
docker run -d --name [CONTAINER_NAME] -p [HOST_PORT]:[CONTAINER_PORT] -v [HOST_PATH]:[CONTAINER_PATH] [IMAGE]

# 예시
docker run -d --name my-nginx -p 1234:80 -v C:\cloud_engineering\Docker\tempDir:/usr/share/nginx/html nginx
```

### Docker 환경변수 주입

```bash
# 단일 환경변수
docker run -d --name [CONTAINER_NAME] -p [HOST_PORT]:[CONTAINER_PORT] -e KEY=value [IMAGE]

# 다중 환경변수
docker run -d --name [CONTAINER_NAME] -p [HOST_PORT]:[CONTAINER_PORT] -e KEY1=value1 -e KEY2=value2 -e KEY3=value3 [IMAGE]

# 파일 기반 환경변수
docker run -d --name [CONTAINER_NAME] -p [HOST_PORT]:[CONTAINER_PORT] --env-file .env [IMAGE]

# 예시: MySQL
docker run -d --name mysql-test \
  -e MYSQL_ROOT_PASSWORD=1234 \
  -e MYSQL_DATABASE=testdb \
  -v mysql-data:/var/lib/mysql \
  mysql:8.3
```

### 컨테이너 내부에서 환경변수 확인

```bash
# 환경변수 전체 확인
env
printenv

# 특정 환경변수 확인
echo $[VARIABLE_NAME]
echo $MY_NAME
```

### Dockerfile 기본 명령어

```docker
FROM <image>[:<tag>]
# 베이스 이미지 지정

WORKDIR <path>
# 컨테이너 내부 작업 디렉터리 지정

COPY <src> <dest>
# 호스트 파일을 컨테이너 이미지에 복사

RUN <command>
# docker build 시 실행되는 명령어

CMD ["executable", "param1"]
# docker run 시 실행되는 기본 명령어 (덮어쓰기 가능)

ENTRYPOINT ["executable", "param1"]
# docker run 시 실행되는 고정 명령어 (덮어쓰기 어려움)

EXPOSE <port>
# 컨테이너가 사용하는 포트 문서화

ENV <key>=<value>
# 환경변수 설정

VOLUME ["/path"]
# 데이터 영속성 목표 디렉터리 지정
```

### Node.js 프론트엔드 앱 Dockerfile

```docker
FROM node:14-alpine

WORKDIR /app

COPY package.json .

RUN npm install

COPY . .

EXPOSE 80

CMD ["node", "app.js"]
```

### SpringBoot 앱 Dockerfile

```docker
FROM eclipse-temurin:21-jre

WORKDIR /app

COPY build/libs/*.jar app.jar

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "app.jar"]
```

### Dockerfile 빌드 및 실행

```bash
# 이미지 빌드
docker build -t [IMAGE_NAME]:[TAG] .
docker build -t my-front-app:v1 .

# 파일명 직접 지정
docker build -t [IMAGE_NAME]:[TAG] -f [DOCKERFILE_PATH] .
docker build -t my-front-app:v1 -f My_Dockerfile .

# 캐시 없이 빌드
docker build --no-cache -t [IMAGE_NAME]:[TAG] .

# 컨테이너 실행
docker run -d --name [CONTAINER_NAME] -p [HOST_PORT]:[CONTAINER_PORT] [IMAGE_NAME]:[TAG]
docker run -d --name my-app -p 8080:80 my-front-app:v1
```

### Node.js 앱 빌드 및 실행

```bash
# 이미지 빌드
docker build -t my-front-app:v1 .

# 이미지 확인
docker images

# 컨테이너 실행
docker run -d --name my-app -p 8080:80 my-front-app:v1
# http://localhost:8080 접속
```

### SpringBoot 앱 빌드 및 실행

```bash
# jar 파일 빌드
./gradlew clean build -x test

# Docker 이미지 빌드
docker build -t my-spring-app:v1 .

# 컨테이너 실행
docker run -d --name my-spring -p 8080:8080 my-spring-app:v1
# http://localhost:8080 접속
```
