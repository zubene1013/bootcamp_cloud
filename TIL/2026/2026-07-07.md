## Key concepts learned

- **Bastion Host**: 프라이빗 서브넷 인스턴스에 접속할 수 없을 때, 퍼블릭 서브넷의 발판 서버를 거쳐 2차 SSH로 들어가는 접속 방식 (NAT Gateway와 다른 개념 — 관리자의 인바운드 접속용)
- **고가용성(HA)**: 하나의 가용영역(AZ)에 장애가 나도 다른 AZ가 대신 서비스를 계속하도록 이중화하는 것
- **IGW vs NAT 게이트웨이**: IGW는 VPC당 1개만 존재하고 재사용 가능, NAT 게이트웨이는 AZ마다 반드시 새로 생성해야 함
- **프라이빗 라우팅 테이블**: AZ마다 반드시 별도로 생성하며, 각 AZ는 자기 AZ의 NAT으로만 라우팅해야 함 (다른 AZ의 NAT로 설정 시 이중화 의미 없음)
- **0.0.0.0/0 (Default Route)**: CIDR로 표현 가능한 모든 IP 주소 범위, 라우팅 테이블에서 "목록에 없는 나머지 전부"를 의미
- **라우팅 우선순위**: 더 구체적인 규칙이 항상 우선 적용됨 (예: 10.1.0.0/16 → local이 0.0.0.0/0보다 먼저 매칭)
- **인스턴스 유형 변경**: 반드시 인스턴스를 Stop 상태에서만 가능 (실행 중 불가)
- **탄력적 IP (Elastic IP)**: 정지 없이 퍼블릭 IP를 유지하거나 즉시 할당하는 방법
- **특권 포트**: 포트 0~1023은 root 권한 필요 (포트 80은 sudo 필수, 1024 이상은 불필요)
- **nohup**: 터미널(SSH 세션) 종료 후에도 프로세스가 계속 실행되게 함, 로그는 nohup.out에 저장
- **ELB (Elastic Load Balancer)**: 여러 대의 서버에 트래픽을 분산시켜주는 서비스

## Commands / Configuration

### SpringBoot 프로젝트 배포

```bash
# JDK 21 설치
sudo apt install openjdk-21-jdk -y

# 프로젝트 Clone
git clone https://github.com/inky4832/aws_springboot_mysql.git

# 빌드
chmod +x gradlew
./gradlew clean build -x test

# 실행 (포트 80 사용)
sudo nohup java -jar [jar파일명] &

# 포트 80이 LISTEN 상태인지 확인
sudo lsof -i :80

# nohup.out 로그 확인 (root 소유)
sudo tail -f nohup.out
```

### application.yml 설정 (B서버용)

```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: validate
  sql:
    init:
      mode: never
```

### EC2 인스턴스 유형 변경 순서

1. 인스턴스 중지 (Stop)
2. 작업(Actions) → 인스턴스 설정 → 인스턴스 유형 변경
3. 인스턴스 시작 (Start)
